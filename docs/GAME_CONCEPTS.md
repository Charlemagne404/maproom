# New-game concept backlog

This backlog combines research opportunities with Maproom's existing data, browser-only architecture and current games. It was ranked on 18 November 2026. Scores are comparative product judgments, not user-study measurements.

**Score key:** `O` originality, `R` replay potential, `E` ease to build (5 = lower effort), `D` data readiness, `V` visual and mobile fit, and `X` separation from existing games (5 = little overlap). Scores run from 1 to 5. The mechanic column states both the core rules and the intended enjoyment hook. Rank favors concepts that are distinct, repeatable and buildable with sourceable data.

## Selected concepts

Riverways and Latitude Ladder were the strongest pair because they add distinct actions and disciplines: tracing physical geography and ordering urban coordinates. Both fit existing local data, can produce seeded rounds without a server, and use shared setup, result, persistence and statistics paths. Free Play city games omit GeoNames records for historical, abandoned, destroyed or sectioned places, while daily city generation retains its established data pool. Both new games remain outside Daily while their difficulty and long-term replay patterns are observed.

Watershed Match, Climate Twins, Terrain Profile and Biomes Mosaic remain proposals, not implementation commitments. Map Projection Match moved into implementation during the 19 November quality mission after official projection-property review showed that the task could be generated from existing local geometry without new datasets. Keep it outside Daily until players have assessed its prompts, effort and replay value.

### Watershed Match source review — 18 November 2026

HydroBASINS remains the strongest identified source for nested basin polygons with upstream/downstream coding. Its product inherits the HydroSHEDS v1 license, which allows use but sets conditions for software distribution and prohibits standalone data redistribution. Maproom has no end-user license, so HydroBASINS is not bundled. The source is based on 15-arc-second HydroSHEDS data; its documentation warns of substantially lower quality north of 60°N.

A second candidate, Basin90m, was reviewed on 19 November. GFZ's data description labels the dataset CC BY 4.0 and describes 667,629 basins larger than 50 km², each paired with its longest river channel. The published workflow also says HydroBASINS basin boundaries were used to divide the 90 m SRTM DEM into 130 processing segments. The available license notes do not resolve whether distributing Basin90m-derived geometry in software also triggers HydroSHEDS v1 terms; that dependency needs clarification before bundling. Basin90m also stops short of the original game brief: SRTM covers 60°N to 56°S, drainage systems intersecting 60°N were removed, and the listed Basin90m schema contains a feature ID and morphometric fields but no documented parent/child IDs. The authors also caution that false rivers were not manually removed, especially in flat and heavily modified terrain. This is a research candidate, not a cleared source or a license conclusion. Next checks: clarify the HydroSHEDS dependency, inspect the available basin/river attributes for useful topology, and test a small set of named rivers before any implementation.

Sources: [HydroBASINS product page](https://www.hydrosheds.org/products/hydrobasins), [HydroSHEDS v1 license and technical documentation](https://data.hydrosheds.org/file/technical-documentation/HydroSHEDS_TechDoc_v1_4.pdf), [Basin90m GFZ data description](https://datapub.gfz-potsdam.de/download/10.5880.GFZ.4.6.2023.004-VEWUOn/2023-004_He-et-al_Data_Description_Basin90m_v1.1.pdf), [Basin90m methods and limitations](https://essd.copernicus.org/articles/16/1151/2024/), and [Basin90m data record](https://doi.org/10.5880/GFZ.4.6.2023.004).

### Future Capitals & Cities mode: Blind coordinates

This is a possible mode inside the existing Capitals & Cities game, not a new game or a commitment for the current release. The player sees a coordinate pair while the map is hidden, makes a location identification or estimate, then submits to reveal the map and compare the answer with the target. Existing bundled city coordinates and marker/reveal components make a local implementation feasible without new services or datasets. The answer surface still needs a clear design decision: a name answer can identify a place from coordinates, while a marker estimate needs a deliberately chosen blank plotting surface if no map may be shown. Any implementation would need hidden-map state, keyboard focus, touch, reduced-motion and reveal behavior coverage, plus a calibrated scoring rule that accounts for distance and the coordinate precision shown. It was documented only; the normal city-placement flow remains the active game.
