# Architecture

## Runtime shape

Maproom is a static React application built with Vite and strict TypeScript. React Router handles `/`, `/explore`, `/statistics`, `/settings`, `/games/:gameId`, `/about`, `/data` and `/privacy`. The build also creates route-specific HTML snapshots for canonical public routes; the Caddy template serves those snapshots first and uses the app shell for client-side routes. There is no application server, account system, analytics script or gameplay API.

The shell lazy-loads the game route page when a game is selected. The route then lazy-loads its game interface from the exhaustive 18-entry `src/games/components.tsx` registry. This keeps route-only map and session code out of the Explore and daily shell. `GamePage` asks `src/geography/data.ts` for the country catalog and only requests generalized country geometry when that game's `requiresCountryGeometry` catalog flag is true. Country Outlines separately loads its detailed Natural Earth 1:10m geometry; other world maps use 1:50m data. Explicit parent-territory relationships split detached possessions into their own Extended identities, while domestic archipelagos remain grouped with their country. The city gazetteer, Natural Earth river centerlines, selected first-level-boundary TopoJSON packages, and game-specific historical or watershed manifests have separate loaders. Historical manifests are validated and cached by their loader; ADM1 packages are requested only for a selected supported country. The service worker precaches the shell, geography catalog and the listed historical/watershed assets, then runtime-caches successful same-origin data requests. The boundary loader corrects spherical ring winding for D3 and repairs UTF-8 names that arrived mojibaked in three source packages.

## Module responsibilities

- `src/geography`: normalized domain types, shared Standard/Extended country eligibility, and lazy fetch/validation for country, city, river, ADM1, and historical collections.
- `src/puzzles`: shared answer normalization, date-in-time-zone and seeded randomness; route graph generation; country-measure and city-distance comparison; Connections board validation; city-order questions; river alias/segment grouping; historical year/sequence and flag/state choices; and geography-grid generation/answer scoring.
- `src/games/catalog.ts`: game titles, routes, categories, setup formats and the explicit daily allowlist. `src/games/components.tsx` maps each stable game ID to its lazy interface. A `Record<GameId, …>` makes missing component registrations a type error.
- `src/games`: eighteen independently implemented game interfaces and their game-specific session controls. `session.ts` gives every game one idempotent result-save path.
- `src/geography/historical` and `src/games/historical-geography`: validated manifests and three historical experiences. Twenty legacy CShapes snapshots remain available to version-1 saved sessions; current historical-map play and Historical States & Empires use 41 curated Cliopatria views; Historical Flags uses a separate 20-entry cited artwork set. Their distinct license terms are documented in [DATA_SOURCES.md](DATA_SOURCES.md).
- `src/games/watershed-match`: validates and loads the local 2025 WBD HUC12 TopoJSON, generates seeded downstream-link questions, and lays out the projected source and candidate polygons.
- `src/persistence`: IndexedDB schema v2 for settings, favorites, result history and resumable game sessions, localStorage fallback, sanitization and JSON import/export.
- `src/statistics`: pure aggregation for totals, per-game records, streaks and a 14-day daily-score trend.
- `src/components/GeoMap.tsx`: D3 Geo Equal Earth/Mercator SVG renderer, keyboard country selection, zoom/pan, city-marker placement and an optional line layer used by river questions.
- `src/app/AppData.tsx`: application data provider that coordinates persistence and live UI state.
- `public/sw.js`: content-fingerprinted precaching of compiled app assets, runtime caching for opened geography data, and a static offline page. The build step replaces the worker's cache-version marker with a hash of the complete static release so data-only updates also clear stale cached files.
- `scripts/data/build-geography.mjs`: reproducible upstream fetch and normalization pipeline; `docs/DATA_COVERAGE.md` is generated from its results.

## Daily puzzle stability

Daily displays six games selected from an explicit eight-game allowlist in `src/games/catalog.ts`. Daily IDs use `gameId:YYYY-MM-DD:vN`. The date is calculated with `Intl.DateTimeFormat` in the saved timezone (initially `Europe/Stockholm`), so daylight-saving offsets are handled by the runtime timezone database. A seeded PRNG and stable shuffle choose daily questions; each game adds a feature-specific suffix to the seed. `PUZZLE_VERSION` supplies version 2, with explicit per-game versions where eligibility or question generation changed; Geography Grid is version 3. Registering a game never adds it to Daily by default. The home and game pages recognize completed dailies by game and local date so a version update does not erase completion marks. Future changes that alter daily answers should receive a deliberate version bump.

The route generator builds an undirected graph from the country catalog's neighbor references, retaining mapless country codes for text entry. Bounded BFS checks every route endpoint pair before it can be played. Geography grids are generated from sourced country attributes at runtime, reject intersections with too few or too many candidates, and require a nine-country distinct-answer assignment. Geography Connections uses country-only fact groups and rejects a board if another supported category creates a second possible four-country grouping.

## Persistence and data flow

The game submits a validated `GameResult` through the app provider. Results are stored by ID in IndexedDB, newest first in application state, and an IDB failure falls back to localStorage. Daily IDs are unique, so a completed daily result cannot be duplicated by refreshing. Interrupted game state is saved as a bounded, versioned session snapshot containing the canonical puzzle seed and game-specific progress. A save restores only when its puzzle ID and save version still match; an unfinished save for a superseded puzzle is discarded while its completed history remains intact. Completion removes the matching active snapshot; export/import carries sessions and remains compatible with version 1 progress exports. Reset removes results and active sessions after in-app confirmation.

Geographic files are public static assets, not user data. The country catalog loads with each game. The 1:50m world geometry loads only for games marked `requiresCountryGeometry`; games that use country facts without an interactive world map skip that file. TopoJSON conversion and region winding normalization load only when a supported first-level boundary package is selected. The 1:10m outlines load only in Country Outlines. The 34k city gazetteer is requested only by Capitals & Cities, Distance & Direction, or Latitude Ladder. The 148-feature river layer is requested only by Riverways. Historical map, atlas and flag manifests are loaded through their validated feature loader. Watershed Match independently validates its small HUC12 sample when its Free Play screen opens; the bundled file is included in the install precache. Provenance is in `public/data/data-manifest.json`, the historical manifests and `region-index.json`, with a human-readable summary in [DATA_SOURCES.md](DATA_SOURCES.md) and country-by-country details in [DATA_COVERAGE.md](DATA_COVERAGE.md).

## Deliberate limits

Country shapes use shared-border TopoJSON quantized at 1e6 and are decoded when a map game requests geometry. The detailed 1:10m outline layer is loaded only by Country Outlines. These generalized boundaries are suitable for world-scale interaction, not legal or cadastral use. Riverways uses named Natural Earth centerlines filtered to scale rank 4 or better; this is neither complete hydrography nor navigational data. Administrative boundary availability and licensing differ by country. City questions use GeoNames cities500 rather than a complete gazetteer. Capitals & Cities uses the full 34,456-place file; Distance & Direction and Latitude Ladder use an order-preserving 12,405-place subset at the 50,000 population floor. Latitude Ladder further limits its pool to places with population of at least 100,000. Population is the 2023 World Bank estimate where available; area and land-border facts follow the country catalog. Route and neighbour answers do not model maritime borders or adjudicate disputed claims. Geography Connections currently groups countries rather than cities. Historical maps are curated reconstructions rather than archival maps: the 20 legacy CShapes-derived snapshots carry CC BY-NC-SA 4.0, while the 41 Cliopatria-derived views and 20 original flag drawings carry CC BY 4.0. All progress is local to one browser and does not synchronize between devices; missed-answer prioritization is available for countries and flags.

## Adding a game

Keep the gameplay loop game-specific and reuse the existing boundaries around it:

1. Add a stable string ID to `GAME_IDS` in `src/geography/types.ts`; IDs are also used in saved history, so do not rename or reuse one.
2. Add one metadata entry in `src/games/catalog.ts` with its route, category, card copy, icon and any setup formats. Leave it out of `DAILY_GAME_IDS` unless a deterministic daily implementation and deliberate puzzle version exist.
3. Add the lazy component to `src/games/components.tsx`. Its exhaustive map must compile for every `GameId`.
4. Put answer generation and scoring that can be tested without React in a focused module under `src/puzzles/`. Validate data at its loader boundary in `src/geography/data.ts` and keep optional data lazy.
5. Build the UI around `GameSettingsMenu` / `GameSettingSelect`, `useGameSession`, and `GameResultsDialog`. These provide the setup overlay, resumable progress, result persistence, replay and statistics integration without forcing unlike games into a universal engine.
6. Update the catalog/data integrity tests, add a gameplay browser test, document rules and attribution, and verify desktop, keyboard, mobile and dark-theme behavior.

The registry test compares metadata IDs with `GAME_IDS`; the component registry type-checks against the same union. The daily allowlist is tested separately so adding a practice game cannot silently change today's puzzle set.
